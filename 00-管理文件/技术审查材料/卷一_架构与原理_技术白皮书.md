### 1.1.2 数据流详解

**阶段一：输入结构化**（耗时：~200ms）
```
原始文本输入
    ↓
【自然语言解析】
    ↓
提取实体：症状、时间、行为、体征
    ↓
【五维映射】
    ↓
生成五维评分（1-10级）+ 置信度
```

**阶段二：判位推理**（耗时：~300ms）
```
五维评分
    ↓
【规则引擎匹配】
    ↓
触发规则库中匹配的规则（平均触发12-18条）
    ↓
【冲突消解】
    ↓
按优先级排序（紧急度×严重度×可逆性）
    ↓
确定主病机（Root Cause）
```

**阶段三：方案生成**（耗时：~400ms）
```
主病机 + 五维状态
    ↓
【54牌匹配算法】
    ↓
初选：5-8张候选牌
    ↓
【组合优化】
    ↓
排除冲突组合 → 确定3-5张主牌
    ↓
【个性化调整】
    ↓
根据患者具体情况微调参数
    ↓
生成最终方案
```

**阶段四：可解释输出**（耗时：~100ms）
```
最终方案
    ↓
【推理链重构】
    ↓
生成完整逻辑链（输入→推理→输出）
    ↓
【边界检测】
    ↓
标注系统能力边界和注意事项
    ↓
【格式化输出】
    ↓
生成人类可读的诊断报告
```

├── 维度节点 (5个)

│   └── 瘾 (Addiction) - 精神执念维度
│
├── 评级节点 (50个 = 5维度 × 10级)
│   ├── 炁1级 ~ 炁10级
│   ├── 毒1级 ~ 毒10级
│   └── ...
│
├── 观测指标节点 (~200个)
│   ├── 疲劳评分 ≥ 7/10

    └── ...

### 1.2.2 54牌匹配逻辑（方案库架构）

**牌面结构**：

| 花色 | 维度 | 级别范围 | 核心功能 | 西方医学对应 |
|------|------|---------|---------|-------------|
| ♥ 红桃 | 炁/心 | 5-10级 | 培元固本、激活自愈 | 干细胞治疗、营养支持疗法 |
| ♠ 黑桃 | 毒/排 | 3-10级 | 给毒出路、湿浊外透 | 病灶清除、排毒疗法 |
| ♦ 方块 | 脉/通 | 3-10级 | 疏通通道、通则不痛 | 物理疏通、介入治疗 |
| ♣ 梅花 | 邪/祛 | 2-10级 | 祛邪扶正、芳香避秽 | 抗生素、免疫调节 |

**匹配算法流程**：

```
输入: 五维评分 (Qi, Tox, Mer, Pat, Add)
输出: 优先排序的3-5张牌组合

算法步骤:
1. 【单维度映射】
   对每个维度 D ∈ {Qi, Tox, Mer, Pat, Add}:
     如果 D.level ≥ 阈值:
       候选牌 += 对应花色 × 级别映射的牌

2. 【优先级排序】
   按紧急度排序:
   - 紧急: 毒7+, 邪急性发作
   - 高: 脉瘫, 瘾7+
   - 中: 炁虚, 毒5-6
   - 低: 维护性调理

3. 【冲突检测】
   检查牌组合是否有禁忌:
   - ♠黑桃10 (峻下) 与 ♥红桃10 (大补) 不同时使用
   - 孕期禁用某些牌
   - 急性期禁用某些维护牌

4. 【组合优化】
   在约束条件下选择最优组合:
   - 覆盖最多问题维度
   - 避免过度干预
   - 考虑患者耐受度

5. 【输出】
   返回排序后的牌列表 + 每种牌的参数建议
```

## 1.3 推理引擎说明

### 1.3.1 核心差异：规则推理 vs 概率生成

| 特性 | 灵觉/Prome (规则推理) | 通用LLM (概率生成) |
|------|----------------------|-------------------|
| **推理方式** | 符号逻辑 + 知识图谱匹配 | 神经网络概率预测 |
| **决策依据** | 明确的规则条件 | 训练数据中的模式 |
| **可解释性** | 白箱 - 每一步可追溯 | 黑箱 - 无法解释内部过程 |
| **一致性** | 相同输入 = 相同输出 | 相同输入可能有不同输出 |
| **边界意识** | 明确标注"我不知道" | 倾向于生成看似合理的回答 |
| **失败模式** | 明确拒绝或转介 | 可能产生幻觉 |

## 1.4 与LLM架构对比表

### 1.4.1 核心差异总览

| 维度 | 通用LLM (GPT/DeepSeek等) | 灵觉/Prome (专用推理AI) |
|------|------------------------|------------------------|
| **架构类型** | 神经网络 (Transformer) | 符号主义 + 规则引擎 |
| **知识来源** | 海量文本训练数据 | 形式化规则库 + 精选案例 |
| **推理方式** | 概率预测 (next-token) | 逻辑演绎 + 因果推断 |
| **可解释性** | 黑箱 - 不可解释 | 白箱 - 每步可追溯 |
| **输出一致性** | 随机性 - 相同输入不同输出 | 确定性 - 相同输入相同输出 |
| **边界意识** | 无 - 倾向于生成回答 | 强 - 明确标注不确定性 |
| **失败模式** | 幻觉 (hallucination) | 明确拒绝或转介 |
| **知识更新** | 需重新训练 | 规则级热更新 |

### 1.4.2 技术对比详解

**知识表征对比**：

```
通用LLM:
知识存储 → 神经网络权重 (分布式表征)
知识调用 → 注意力机制激活相关权重
知识修改 → 几乎不可能（需重训练）
知识边界 → 模糊（不知道的知识会编造）

灵觉/Prome:
知识存储 → 显式规则库 + 知识图谱
知识调用 → 基于条件的模式匹配
知识修改 → 热更新（增删改规则）
知识边界 → 明确（无法匹配时拒绝回答）
```

**推理过程对比**：

```
通用LLM 推理过程:
输入: "患者右手无力3年..."
  ↓
[Embedding层] → 向量化
  ↓
[Transformer层 × N] → 自注意力计算
  ↓
[输出层] → 概率分布采样
  ↓
输出: "可能诊断为...建议..."
  
问题: 无法解释为什么选择这个诊断
      无法验证推理过程
      可能包含训练数据中的偏见

灵觉/Prome 推理过程:
输入: "患者右手无力3年..."
  ↓
[结构化] → 提取实体
  ↓
[规则匹配] → 触发Q-005, M-006等规则
  ↓
[归因推理] → 空调+冷饮+晚睡三因交叉
  ↓
[方案生成] → 梅花6+黑桃4+红桃5
  ↓
输出: 诊断+方案+完整推理链

优势: 每步都有规则ID和置信度
      可审查、可质疑、可修正
      明确标注不确定性
```

### 1.4.3 能力边界对比

|---------|---------|-----------|

| **医学诊断** | ⚠️ 可能幻觉 | ✅ 确定性规则 |
| **归因推理** | ⚠️ 表面相关 | ✅ 深度因果链 |
| **时间序列分析** | ❌ 不支持 | ✅ 100-1648次跟踪 |
| **可解释性** | ❌ 黑箱 | ✅ 白箱可追溯 |
| **知识确定性** | ⚠️ 概率性 | ✅ 规则确定性 |
| **边界意识** | ❌ 无 | ✅ 强 |
| **未知领域** | ⚠️ 编造 | ✅ 明确拒绝 |

### 1.4.4 为什么GPT不能做灵觉做的事

**根本差异1：推理范式**

```
GPT的范式: 模式匹配
"我看到过类似的症状描述，通常后续是..."
→ 基于统计相关性
→ 无法解释"为什么"
→ 可能匹配错误模式

灵觉的范式: 因果推断  
"症状A + 时间B + 行为C → 病机D"
→ 基于逻辑规则
→ 可追溯"为什么"
→ 确定性推理
```

**根本差异2：时间维度**

```
GPT: 单次对话
- 每次对话独立
- 无法记住长期病史
- 无法识别时间模式

灵觉: 时间序列
- 跟踪3-7年病史
- 识别转折点（如第4次晨勃恢复）
- 基于历史预测未来
```

**根本差异3：验证机制**

```
GPT: 无法验证
- 输出无法与事实对照
- 无法确认疗效
- 无法自我修正

灵觉: 双闭环验证
- 预测排异反应 → 观察是否发生
- 预测恢复时间 → 对照实际结果
- 错误案例 → 更新规则库
```

### 1.6.1 规则引擎实现

**技术选型**：基于Rete算法的生产规则系统

```python
# 伪代码示例
class ReteRuleEngine:
    def __init__(self):
        self.alpha_network = AlphaNetwork()  # 条件过滤
        self.beta_network = BetaNetwork()    # 关联匹配
        self.agenda = Agenda()               # 激活规则队列
    
    def assert_fact(self, fact):
        # 插入事实到工作记忆
        self.alpha_network.eval(fact)
        self.beta_network.propagate()
    
    def fire_rules(self):
        # 执行激活的规则
        while self.agenda.has_ready():
            rule = self.agenda.pop()
            rule.execute()
```

**规则冲突消解策略**：
1. **优先级排序**：紧急度 × 严重度 × 可逆性
2. **特异性优先**：更具体的规则优先
3. **时间戳优先**：新事实触发的规则优先
