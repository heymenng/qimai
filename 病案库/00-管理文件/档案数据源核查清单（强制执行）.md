- ❌ 用"推测""可能""应该"的内容填充档案

- ✅ 每个数据点必须能在原始记录中找到对应
- ✅ 任何"弟子补充"的内容必须用【弟子注】标注，且不得作为诊断依据

## 操作流程（每次建档/更新前必须执行）

### Step 1: 数据源确认（ACP-00）

**必须回答以下问题，并记录答案**：

| 序号 | 问题 | 答案 | 验证方式 |
|------|------|------|---------|
| 1 | 患者姓名是谁提供的？ | | 核对原始对话记录 |
| 2 | 患者症状数据从哪来的？ | | 核对原始调理记录/反馈表 |
| 3 | 调理次数是谁记录的？ | | 核对原始调理日志 |
| 4 | VAS评分是谁打的？ | | 核对原始评分表 |
| 5 | 排毒反应（痧色、毒油）是谁观察的？ | | 核对原始照片/描述 |
| 6 | 有没有任何数据是弟子自己编的？ | **必须回答"没有"** | 自我诚实检验 |

**如果第6题答案不是"没有"** → **立即停止操作，删除已生成内容**

---

### Step 2: 原始数据归档

**每次建档/更新后，必须将原始数据文件归档**：

```
原始数据归档路径：
病案库/00-管理文件/原始数据源/{患者编号}/

必须包含：
├── 患者基本信息.txt（师父或调理师提供的原始文字）
├── 调理记录/（每次调理的原始反馈）
├── 排毒反应照片/（如有）
├── 对话截图/（如有）
└── 数据来源声明.md
```

**数据来源声明模板**：

  - [ ] 微信对话截图
  - [ ] 调理反馈表照片
  - [ ] 语音转录文字
  - [ ] 现场记录
  - [ ] 其他：_______

**数据完整性**：
  - [ ] 包含患者基本信息
  - [ ] 包含调理记录
  - [ ] 包含症状反馈
  - [ ] 包含排毒反应描述

**弟子核查**：
  - [ ] 已核对原始数据与档案内容一致
  - [ ] 未发现虚构内容
  - [ ] 未发现改编内容

## 真实性核查制度

### 即时核查（每次操作后）

**弟子自检清单**：
- [ ] 已确认数据来源
- [ ] 已归档原始数据
- [ ] 已在档案头部标注数据源声明
- [ ] 已核对所有数据点与原始记录一致
- [ ] 未发现虚构内容
- [ ] 未发现改编内容

### 定期核查（每周）

**每周五执行**：
1. 回顾本周所有新建/更新的档案
2. 逐一核对数据源声明
3. 抽查原始数据文件是否存在
4. 核对档案内容是否与原始数据一致

**核查记录归档**：
```
病案库/00-管理文件/真实性核查记录/
├── 2026-04-25_周核查.md
├── 2026-05-02_周核查.md
└── ...
```

### 月度审计（每月）

**每月最后一日执行**：
1. 统计本月新建/更新档案数量
2. 统计数据来源分布（师父提供/调理师提供/其他）
3. 自查是否有"无数据源"的档案
4. 向师父提交月度真实性报告

## 技术防护措施

### 1. 数据源文件强制读取

**每次建档前，系统必须**：
1. 检查是否存在原始数据文件
2. 如果不存在 → 拒绝生成，提示"缺少数据源"
3. 如果存在 → 读取并显示数据源摘要，供弟子确认

### 2. 自动比对机制

**档案生成后，系统自动**：
1. 提取档案中的关键数据（姓名、年龄、症状、VAS评分）
2. 与原始数据文件进行比对
3. 如果发现不一致 → 高亮提示，要求确认

### 3. 数据源声明完整性检查

**档案保存前，系统检查**：
1. 档案头部是否包含【数据源声明】模块
2. 声明内容是否完整（来源、日期、路径）
3. 如果缺失 → 拒绝保存
