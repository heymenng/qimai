# 数据安全合作协议（炁脉医学AI × 平安健康保险）

**协议编号**: QMAI-PAH-DSA-2026-001  
**签订日期**: 2026年3月  
**合作方**: 炁脉医学AI系统（硅基传承者）× 平安健康保险股份有限公司

---

## 一、核心原则：数据主权归属

### 1.1 数据所有权声明

| 数据类型 | 所有权归属 | 使用权限 | 删除权 |
|---------|-----------|---------|--------|
| **原始诊疗数据** | 客户（投保人）本人 | 客户独占 | 客户随时可要求彻底删除 |
| **脱敏分析数据** | 客户授权后，保险公司持有使用权 | 仅限约定场景 | 客户撤回授权时同步删除 |
| **AI训练数据** | 采用联邦学习，原始数据不出域 | 仅模型参数共享 | 客户退出时模型遗忘 |
| **诊断逻辑/知识库** | 炁脉医学传承体系 | 授权使用，不得转售 | 合作终止时收回 |

### 1.2 "管道哲学"声明

> **炁脉医学AI的定位是"管道"而非"容器"**
> 
> - 数据如水流经管道，不在管道中蓄积
> - 管道只提供处理能力，不拥有水质所有权
> - 客户随时可断开管道，带走自己的水源

### 2.2 技术保障措施详表

| 层级 | 技术措施 | 实现方式 | 验证标准 |
|------|---------|---------|---------|
| **传输安全** | TLS 1.3 + mTLS双向认证 | 证书 pinning，防中间人攻击 | 通过OWASP ASVS L3测试 |
| **存储安全** | AES-256-GCM + 密钥分割 | 客户密钥分片，多方共管 | 通过等保三级认证 |
| **计算安全** | 可信执行环境(TEE) | Intel SGX/AMD SEV | 内存加密，防侧信道攻击 |
| **访问控制** | RBAC + ABAC + 零信任 | 动态权限，最小特权原则 | 每次访问需重新认证 |
| **审计追溯** | 不可篡改日志链 | 区块链存证（Hyperledger） | 所有操作可追溯至个人 |
| **数据脱敏** | 差分隐私 + k-匿名 | 统计查询加噪，个体不可识别 | ε≤1的差分隐私预算 |

## 三、业务场景合规矩阵

### 3.1 B2B企业健康管理场景

| 业务环节 | 数据类型 | 安全措施 | 合规依据 |
|---------|---------|---------|---------|
| **企业上传员工体检报告** | 个人健康信息（PHI） | 上传即加密，企业HR不可见详细内容 | 《个人信息保护法》第28条 |
| **AI生成健康评估** | 诊断建议 | 仅员工本人可见，企业仅看统计摘要 | 《数据安全法》第21条 |
| **团体风险定价** | 聚合统计 | 差分隐私处理，k≥20人组才出数据 | 《健康保险管理办法》 |
| **干预效果追踪** | 纵向数据 | 员工授权期内可用，离职即冻结 | 劳动合同+隐私协议双授权 |

### 3.2 B2C保险产品场景

| 业务环节 | 数据类型 | 安全措施 | 用户权利 |
|---------|---------|---------|---------|
| **投保健康告知** | 既往病史 | 仅用于核保，不用于其他目的 | 知情权：用途明确告知 |
| **AI辅助核保** | 风险评分 | 算法可解释，拒绝需说明理由 | 解释权：要求人工复核 |
| **保单期间健康管理** | 行为数据 |  opted-in（可选加入） | 撤回权：随时退出数据收集 |
| **理赔材料审核** | 医疗记录 | 仅本次理赔使用，不留存 | 删除权：理赔结束后30天删除 |

## 四、应急响应与数据泄露预案

### 4.1 事件分级响应

```
┌────────────────────────────────────────────────────────────┐
│                   数据安全事件响应流程                       │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  【P0级】数据泄露确认（如：数据库被拖库）                    │
│   ├─ 15分钟内：启动应急响应小组，断开受影响系统             │
│   ├─ 1小时内：通知保险公司+CPO+法务，评估影响范围           │
│   ├─ 24小时内：向监管部门报告，通知受影响客户               │
│   ├─ 72小时内：发布事件公告，提供补救措施                   │
│   └─ 30天内：完成根因分析，系统加固，第三方审计             │
│                                                            │
│  【P1级】疑似入侵（如：异常访问模式）                        │
│   ├─ 1小时内：隔离可疑会话，强化监控                        │
│   ├─ 4小时内：安全团队调查，确定是否真实入侵                │
│   └─ 24小时内：向保险公司通报调查结果                       │
│                                                            │
│  【P2级】内部违规（如：员工越权访问）                        │
│   ├─ 立即：暂停涉事员工权限，保全日志                       │
│   ├─ 24小时内：内部调查，HR介入                             │
│   └─ 视情节：纪律处分/法律追责/监管通报                     │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

### 4.2 数据泄露赔偿责任

| 泄露原因 | 责任方 | 赔偿范围 | 最高赔偿限额 |
|---------|-------|---------|-------------|
| 炁脉AI系统漏洞 | 炁脉医学AI | 直接损失+信用修复+监管罚款 | 年度合同额的300% |
| 保险公司操作不当 | 平安健康 | 内部追责，炁脉AI协助修复 | 由保险公司承担 |
| 第三方攻击（不可抗力） | 双方共担 | 应急成本+客户通知成本 | 按保险条款执行 |
| 客户自身原因（密码泄露） | 客户自担 | 协助恢复，不承担赔偿责任 | 无 |

## 六、合作终止与数据处置

### 6.1 终止场景

| 终止类型 | 触发条件 | 数据处置方式 | 时间要求 |
|---------|---------|-------------|---------|
| **合同到期不续约** | 双方协商 | 客户数据返还或删除（客户选择） | 90天内完成 |
| **单方违约终止** | 重大数据泄露/持续违规 | 立即冻结数据，争议解决后处置 | 48小时内冻结 |
| **业务转型终止** | 保险公司退出健康险市场 | 客户数据迁移至客户指定位置 | 180天内完成 |
| **监管要求终止** | 政策变化导致无法合规 | 按监管部门指示处置 | 即时执行 |

### 6.2 数据销毁标准

```
数据销毁流程（NIST SP 800-88 Rev.1 标准）

Step 1: 数据分类清点
   └─ 清点所有存储介质（数据库、日志、备份、缓存）
   
Step 2: 客户确认
   └─ 向客户发送数据销毁清单，获得书面确认
   
Step 3: 执行销毁
   ├─ 在线数据：安全删除（DoD 5220.22-M标准，7次覆写）
   ├─ 备份数据：物理销毁（磁盘粉碎/消磁）
   └─ 日志数据：保留审计所需后，按 retention policy 销毁
   
Step 4: 销毁证明
   └─ 提供第三方销毁证明+炁脉AI内部销毁报告
   
Step 5: 验证审计
   └─ 保险公司可派员现场见证销毁过程
```

## 七、特别条款：AI伦理与可解释性

### 7.1 算法透明度承诺

| 诊断输出 | 可解释性要求 | 实现方式 |
|---------|-------------|---------|
| **五维诊断结果** | 必须说明每个维度的判断依据 | 引用症状+体征+检测数据 |
| **54张牌选方** | 必须说明选牌逻辑 | 展示决策树路径 |
| **十八变预警** | 必须基于历史案例统计 | 提供相似案例参考 |
| **排异预告** | 必须说明生理机制 | 引用五维理论解释 |
