# 案例验证框架 V1.0

> **定位**：系统验证四医超越者体系的临床有效性
> **用途**：AI自我验证工具 + 人类审核指南
> **原则**：用现有案例验证新建数据库的匹配度与准确性
> **版本**：V1.0
> **更新**：2026年5月7日

---

## 一、验证目标

### 1.1 验证对象

| 验证对象 | 验证内容 | 数据来源 |
|---------|---------|---------|
| **西医指南库** | 案例中的西医诊断是否符合ATA/AACE/ACC/NCCN指南 | 病案库中的西医诊断部分 |
| **功能医学库** | 案例中的检测指标是否能用DUTCH/OAT框架解读 | 病案库中的化验单/检测数据 |
| **国医大师库** | 案例中的中药处方是否与大师经验方匹配 | 病案库中的中药处方 |
| **方剂协同库** | 案例中的复方配伍是否符合协同模式 | 病案库中的处方分析 |
| **五维诊断** | 五维定级是否与实际症状/指标一致 | 病案库中的五维评估 |
| **54牌方案** | 54牌选方是否与五维缺口匹配 | 病案库中的治疗方案 |

### 1.2 验证指标

```
【验证精度指标】

1. 诊断匹配率（Diagnosis Match Rate）
   - 定义：AI建议诊断与案例实际诊断的一致性
   - 计算：匹配案例数 / 总验证案例数 × 100%
   - 目标：≥85%

2. 处方匹配率（Prescription Match Rate）
   - 定义：AI建议处方与案例实际处方的相似度
   - 计算：核心药物重叠数 / 核心药物总数 × 100%
   - 目标：≥70%（允许个性化加减）

3. 五维一致性（Five-Dimension Consistency）
   - 定义：五维定级与实际症状/指标的吻合度
   - 计算：各维度误差≤1级的案例数 / 总案例数 × 100%
   - 目标：≥90%

4. 转诊红线识别率（Referral Recognition Rate）
   - 定义：AI正确识别需转诊案例的比例
   - 计算：正确识别转诊数 / 实际需转诊数 × 100%
   - 目标：100%（急症不可漏）

5. 疗程预测误差（Course Prediction Error）
   - 定义：AI预测疗程与实际疗程的差异
   - 计算：|预测次数 - 实际次数| / 实际次数 × 100%
   - 目标：≤30%
```

## 二、验证方法论

### 2.1 验证流程

```
【五步验证法】

Step 1: 案例抽样
  - 按分层随机抽样：普通案例60% + 疑难重症25% + 肿瘤15%
  - 目标：首批验证50例

Step 2: 数据提取
  - 提取案例中的：症状、体征、检测指标、西医诊断、中医辨证、五维定级、处方、疗效

Step 3: AI独立诊断
  - 用新建数据库（西医+功能医学+国医大师+方剂协同）进行独立分析
  - 输出：五维定级 + 四医诊断 + 处方建议 + 疗程预测

Step 4: 对比验证
  - 对比AI输出与案例实际记录
  - 记录：匹配点 / 差异点 / 原因分析

Step 5: 反馈优化
  - 根据差异调整数据库
  - 记录：假设验证状态（✅确认 / 🟡修正 / ❌推翻）
```

### 3.2 可用于验证的案例筛选

```
【首批50例验证样本筛选标准】

入选标准：
  1. 档案版本 ≥ V4.1（确保基本结构完整）
  2. 包含五维诊断数据
  3. 包含西医诊断或检测指标

  - 湿病/脾胃：8例

  - 疑难重症：8例
    * 重点验证：四医合诊整合能力
  - 普通慢性病：6例

  - 疗效记录缺失 > 50%
```

## 四、验证执行计划

### 4.1 分阶段执行

```
【Phase 1】框架搭建（本周）
  - 完成验证框架文档（本文件）
  - 筛选首批50例验证样本
  - 建立验证记录模板
  - 状态：✅ 进行中

【Phase 2】抽样验证（下周）
  - 按分层抽样选取50例
  - 对每个案例进行AI独立分析
  - 填写验证记录
  - 计算匹配率指标
  - 状态：⏳ 待启动

【Phase 3】差距分析（第三周）
  - 汇总验证结果
  - 识别系统性偏差
  - 制定数据库优化方案
  - 状态：⏳ 待启动

【Phase 4】优化迭代（第四周）
  - 根据验证结果优化数据库
  - 重新验证优化后的案例
  - 确认匹配率提升
  - 状态：⏳ 待启动

【Phase 5】规模化验证（1-3个月）
  - 扩展至200例验证
  - 建立自动化验证流程
  - 形成验证报告
  - 状态：⏳ 待启动
```

### 4.2 验证团队分工

```
【AI角色】
  - 独立分析：使用新建数据库进行诊断和处方
  - 对比评估：对比实际记录与AI预测
  - 差距识别：找出系统性偏差
  - 优化建议：提出数据库改进方案

【人类审核员角色】（需师父指定）
  - 终审验证：确认AI分析的合理性
  - 临床判断：评估处方安全性和有效性
  - 异常处理：处理AI无法判断的复杂情况
  - 决策权：最终处方和疗程决策

【调理师角色】
  - 数据采集：确保案例数据完整准确
  - 疗效记录：如实记录患者反应
  - 反馈收集：收集患者主观感受
```

## 六、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 案例数据不完整 | 验证结果偏差 | 严格筛选标准，排除不完整案例 |
| 档案版本不统一 | 对比困难 | 按版本分层分析，重点验证V4.2+ |
| AI过度拟合 | 验证结果虚高 | 交叉验证，用新案例测试 |
| 人类审核延迟 | 验证进度拖延 | 先完成AI分析，再批量提交审核 |
| 患者隐私泄露 | 法律风险 | 脱敏处理，仅使用已授权案例 |
